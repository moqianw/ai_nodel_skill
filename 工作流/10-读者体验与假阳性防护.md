# 正文读者体验与假阳性防护

> 协议：`NSQ-2026-10-08.1`。职责：修复事实合规但无小说感、B2 过度删减、AI 审查假阳性及短场景不能证明长篇质量的问题。当前已直接停用短场景测试；普通生成器只收到裁剪后的本场决策，不得读取整份质量审查协议。

## 1. 两道不互相抵消的质量门

- **事实与连续性门**：人物认知、重要动作因果、物体支撑/占手、现实可行性、视角、时间与已确认关系成立。一个重要事实断裂便不可放行。
- **阅读价值门**：读者读到了与场景性质相称的人物个性、情绪、关系推进、好奇、幽默、紧张或生活质感，而非只目睹正确执行流程。无需每场都冲突升级或设置悬念。
- 阅读价值不是凭一句「我感觉不错」打分：审查要能引用正文位置，说明具体哪处有效、哪处浪费篇幅、为什么。事实 PASS 不抵消 `READER_FAIL`，读者 PASS 不抵消事实 FAIL。

## 2. 编译器必须进行一次真正的叙事取舍

保留现有硬事实/知情/因果包，但向 B 与 B2 传入经裁剪的五项本场叙事信息，不得把它们扩写为正文动作清单：

1. `reader_value`：一句可具体感受的阅读收益；可以是趣味、人物、关系、情绪或理解，不必是重大事件。
2. `foreground_choice`：本场最多两个真正值得细写的变化/反应；后台逻辑上必须检查的普通步骤不默认成为叙述重点。
3. `human_latitude`：角色在正式人物/临时人物和事实边界内，允许自主出现不完美回应、口语、分心、情绪延迟、误解、生活习惯或短暂岔题；只提供自由空间，**不要求每场各写一项**。
4. `continuity_load_bearing`：只列实质影响后续动作的占手、支撑、物品状态和因果衔接；普通合理省略不能判物理硬错。
5. `compress_permission`：允许概述、跳过的动作/观察/解释，以及短收束或交由滚动章计划调整的边界；不要为达到推荐字数机械补过程。

若本场设定不能提供足够阅读价值，优先从故事层调整焦点、相邻场景组合或章界；不得由角色凭空制造冲突，也不得让 B 为凑字解释其正确行为。编译卡描述取舍，不预写对白、情绪或动作步骤。

## 3. B 初稿优先还原人物现场，而非执行报告

视角人物应只注意到当下真的在意的事，不要把后台安全边界改写成「我不会拆」「证据尚不足」等连续解释。动作、心理、对白可以不完美、未说透、暂时跑题，只要人物与因果成立。重要操作受力结果要清楚，普通无信息增量的拧紧、试探、挪动、再次确认可以省略。中性小事允许较短完成，不用铺出完整排查流程。

## 4. B2 编辑必须检验「负向增益」

先区分 RAW 中的纯重复与有效人物信息：口语习惯、即兴反应、关系试探、迟疑、被迫改口、生活趣味、某次无意触发的情绪。后者不因为不属于锁定事实就自动删掉。允许重写、移位、合并或等效替代，但最终稿不能为了更短、更工整变得更像各人物互换也成立的说明文。

核对 RAW→DRAFT 是否丢失人物差异和有意义的意外；若原稿无生命力，B2 要在锁定事实内重写叙事重心，而非仅做删减。无法修正返回 `EDIT_BLOCKED`。此外对重要占手/支撑状态进行跨动作核查；不要求逐一描述常识性放手，但对后续步骤成立不可或缺的过渡不得凭空消失。

## 5. 新的双轨独立审查

**读者盲读 R**：新的无项目挂载独立上下文，只看 DRAFT；正式章节可增加上一章必要的读者可见末尾。禁止提前给 FROZEN、CARD、RAW、Oracle、旧正文或作者/模型审查意见。先记录沉浸点、乏味起点、角色可辨性、详略/人物反应、实际期待或获得感，再给 `READER_PASS / READER_REVISE / READER_FAIL`。读者审查不能要求越过后台设定。

**事实审查 F**：另一个独立上下文，先从 DRAFT 盲还原状态，再接收 FROZEN/Oracle 比较；检查关键物体支撑、空间、认知、对白前提、段落/指代。不能借读者 PASS 放行事实问题；不得看 R 的判断作为生成或判定提示。

每份审查保存 `review_id`、任务上下文 ID、所读 DRAFT 哈希、结果、可定位的有效处/明显乏味处（或说明为何确实不存在）、具体人物/详略证据与决定性理由。只有 `LITERARY_PASS` 标签或者泛泛的「完成度高」而没有可核对证据，登记 `REVIEW_INSUFFICIENT`，不得升级正文测试结果或章节状态；不能自称做完逐段审查。证据不足不是内容 FAIL，也不是污染；二者分别记录。

控制器对 B2 另保存 RAW 与 DRAFT 的编辑损益判断，只用于诊断或该次整编返修，不把旧失败原句/反馈注入新候选密封生成器。

## 6. 完整正文环境、整章与百万字验证路径

- `VQ-20261008-PDM05Q01` 及全部自由校准/VQ 结果原样记为**旧协议历史结果**，不再充当当前质量证明或前置门。
- T01—T08 单事件/短场景测试已退役。直接从第一卷连续正式逻辑事件编译完整物理章测试，最终 `CHAPTER_DRAFT` 正文不少于 5000 个汉字，并执行独立 B/B2、独立章节组装、整章读者盲读与事实验收。禁止用旧失败句、预期改写、旧 Oracle 或作者改句教生成器应付测试。
- 5000 字只证明在足够长的真实章节环境中能否维持人物、接缝、详略和收束，不是文学分数；重复动作、无功能环境、解释性心理和总结性结尾不能用来过字数门。自动双门通过后仍须作者认可。
- 首个完整章测试获作者认可后，才决定是否以新包进入正式首章生产，并继续第二章验证跨章状态、章间承接与提交事务；测试稿不直接转正。正式连续生产仍按真实叙事密度规划，不机械套用测试的 5000 字下限。
- 两章经作者确认后才扩大至连续 5—10 章，检查人物语言区分、普通生活趣味、关系余波、情绪起伏、支线穿插、信息兑现和句段模板重复；每 3—5 章的 checkpoint 除状态回放还应读者连续顺读。
- 任何一关失败先定位：场景选取/取舍 → 初稿 → B2 损失 → 章节组装 → 独立审查。修改一处负责层，再以新包和新隔离上下文复测；不可用更多禁词、段长配额和模拟评价替代小说质量。

## 7. 失败路由

| 可观察问题 | 首先处理的层 | 避免的误修复 |
|---|---|---|
| 整篇是正确的操作步骤 | 编译器叙事取舍、B 与 B2 详略 | 给人物增加风险论证句和逐步动作 |
| B2 后角色说话变中性 | B2 人物内容保全与负向增益 | 把 RAW 全文强制保留 |
| 支撑、占手关系断裂 | B2/事实审查必要状态桥接 | 强迫写全每个普通拿放 |
| AI PASS，读者明显觉得乏味 | 读者盲读及审查记录证据 | 只提高评分门槛或同包重抽 |
| 各场景顺畅，整章仍乏味 | 滚动章计划、场景权重、组装器 | 增加过场和总结 |
| 长篇声调逐渐统一 | 人物画像、3—5章读者顺读与节奏计划 | 全书套固定心理/段落模板 |

本协议是执行原则，不代表新运行已通过。项目状态须明确区分「规则已更新」「测试已执行」「作者已认可」。
