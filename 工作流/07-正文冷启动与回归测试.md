# 完整正文环境测试与回归

> 协议版本：`FCT-2026-10-09.1`
> 当前入口：只运行正式剧情的完整物理章测试；T01—T08 单事件、单场景和其他短篇测试全部退役。

## 1. 目的与硬边界

本测试验证的不是模型能否写出一个局部片段，而是当前系统能否在真实小说环境中持续处理章首进入、多个叙事阶段、场景承接、人物关系、信息释放、详略分配和自然章末。

每个有效 attempt 必须同时满足：

- 使用 `VALID` 单卷设计中的连续正式逻辑事件，不使用中性种子或脱离主线的短夹具；
- 建立完整物理章的测试专用章计划，明确章首、核心问题、事件/场景顺序、读者获得、章末落点和整章离开状态；
- 最终交付物是唯一的 `CHAPTER_DRAFT`，正文不少于 **5000 个汉字**；标签、标题、报告和元数据不计入；
- 5000 字是测试覆盖硬下限，不是填充指标。自然内容不足时回到章计划扩大连续正式事件范围或重编章界，不得补重复动作、静态环境、解释性心理、同义总结或无动机收尾；
- 使用独立 B、独立 B2、独立章节组装器、独立读者 R 和独立事实验收器 F；同一共享上下文中的角色扮演不计隔离；
- 测试稿不提交正式章节状态增量，不标为 `VALID`。只有作者认可后，才决定是否以新包进入正式生产。

旧 `03-冷启动回归生成夹具.md`、`04-冷启动回归验收基准.md` 及 T01—T08 结果均为 `DEPRECATED` 历史资料。不得把旧 Oracle、失败正文、作者改句或验收意见发送给本轮生成侧。

## 2. 测试专用章计划

控制器从正式逻辑事件中选择足以形成完整章节的连续范围。测试专用章计划只负责本次 attempt，不代替正式卷级场景地图或滚动计划，至少记录：

- `run_id / test_chapter_id / attempt`；
- 来源逻辑事件及其自然先后关系；
- 卷首或上一章读者可见必要末尾；
- 章首即时问题、主要叙事发动机和各场景权重；
- 必须完成、不得提前完成、允许留待后章的内容；
- 场景之间的时间、空间、行动权、视角和关系承接；
- 读者完成本章后的实际获得与自然章末；
- 目标区间与硬下限。测试建议目标为 5500—7500 个汉字，硬下限 5000；
- `scene_map / production_rolling_plan = N/A` 时的明确说明。

不得把预期台词、微动作、标准修辞或旧失败答案写进章计划。若事件范围无法在不稀释的情况下形成 5000 字完整章，编译阶段返回 `CHAPTER_SCOPE_BLOCKED`，不得先写短稿再拉长。

## 3. 上下文隔离与强制链

完整章测试至少使用下列互相隔离的上下文：

1. **控制器/编译器**：读取正常正式资料和测试专用章计划，冻结有序场景包及章节组装包；
2. **密封初稿生成器 B**：每个场景只读对应冻结包，输出 `package_id + RAW_DRAFT`；
3. **叙事结构编辑器 B2**：新上下文只读同一冻结包与本次 RAW，输出 `package_id + SCENE_DRAFT`；
4. **章节组装器 CA**：新上下文只读章节组装包、有序 `SCENE_DRAFT` 及必要可见前文，输出唯一 `chapter_id + CHAPTER_DRAFT`；
5. **读者盲读 R**：只读必要可见前文与完整 `CHAPTER_DRAFT`；
6. **事实验收 F**：第一阶段只读与 R 相同的正文材料并冻结整章盲还原，第二阶段才接收冻结包、组装包与验收协议进行比较。

强制链为：

`连续正式事件 → 测试专用章计划 → 场景编译/许可 → FROZEN 场景包 → 独立 B → RAW_DRAFT → 独立 B2 → SCENE_DRAFT → 冻结章节组装包 → 独立 CA → CHAPTER_DRAFT（≥5000 汉字）→ 独立 R/F → 作者判断 → 测试记录`

若整章只包含一个强连续场景，仍须分别建立场景包和章节组装包，CA 不得由 B2 同上下文兼任。若任何角色读取完整仓库、旧测试正文、旧 Oracle、验收意见或生成推理，本 attempt 的相应隔离资格失效。

## 4. 生成与整编

B 与 B2 沿用 `03-单卷展开与正文生产.md` 和 `08-正文运行时协议.md` 的输入边界。B 负责完整初稿，不输出分析；B2 把 RAW 当作可重构素材，在冻结事实、认知、因果和离开状态内重新安排详略、段落、心理、动作和收束。

B2 必须特别检查长章中容易累积的问题：

- 段内主轴是否稳定，是否频繁在人物、物体、身体部位和环境之间无功能换轴；
- 段首代词能否由紧邻前文唯一恢复；
- 句间、段间和场景间是否存在真实的继续、反应、打断、结果—选择或明确跳转；
- 人物状态变化是否有可见偏差并被后文接收，而非只有动作、对白和环境；
- 同一判断是否被动作、心理和旁白重复解释；
- 环境、神态、心理和普通动作是否有功能，是否只是为篇幅存在；
- 章末是否落在有效动作、关系余波、选择或未完成压力上，而不是总结本章意义。

单个场景自然偏短不是失败；控制器应通过正确的章节范围和场景权重满足整章覆盖，不能要求 B/B2 在场景内部注水。

## 5. 独立章节组装

CA 按 `CA-2026-10-09.1` 工作，只处理整章组织：修复章首进入、场景承接、跨场重复、人物/物体重定位、详略比例和自然章末。CA 可以压缩场景重入与同义回顾，但不得改变冻结事实、认知上限、事件因果或离开状态，也不得为了达到 5000 字新增事件和解释。

CA 输出后由控制器只做格式与字数核验：

- 少于 5000 个汉字：记 `LENGTH_GATE_FAIL`，不得交给 R/F，也不得要求 CA 注水；回到章计划扩大自然范围后以新包重跑；
- 达到下限但明显靠重复或无功能内容撑长：交由 R/F 按文学质量失败，不因字数合格放行；
- 包外新增事实或整章成立必须改变场景锁定层：`ASSEMBLY_BLOCKED`。

## 6. 整章双轨验收

**读者盲读 R**只看完整章及必要可见前文，检查：章首是否能进入、人物是否可辨、前后文和段落是否连贯、叙事详略是否自然、心理与神态是否真实、是否出现程序化动作循环、场景切换是否生硬、章末是否自然、读完整章实际获得了什么。结论为 `READER_PASS / READER_REVISE / READER_FAIL`，必须给出可定位正文证据。

**事实验收 F**先盲还原整章的时间、空间、人物认知、关系、重要物体、动作因果、场景转换、读者获得和章末状态，并明确无法确定项；冻结后才与场景包、组装包及验收协议比较。旧短测 Oracle 不进入此流程。

整章至少检查四层：

1. 事实、物体、空间和动作可达性；
2. 人物认知、对白前提、关系和信息边界；
3. 场景顺序、章内因果、读者获得和离开状态；
4. 段内主轴、段首指代、叙事接缝、详略、重复、人物表层与自然收束。

事实 PASS 不能抵消 `READER_FAIL`，读者 PASS 也不能抵消事实失败。读取比较材料后的内容失败立即结束该 attempt，不得把答案反馈给原 B/B2/CA 定向修到通过。

## 7. 结果与停止条件

结果分别记录内容结论和隔离资格：

- `PASS / FAIL / BLOCKED / INVALID`；
- `VERIFIED / UNVERIFIED / BREACHED`。

只有 `CHAPTER_DRAFT ≥ 5000 汉字`、R 与 F 均通过、隔离资格 `VERIFIED` 且作者认可，才记为“完整正文环境测试通过”。自动通过只能提交作者，不能代替作者判断，也不自动提交正式正文状态。

单轮最多三个全新 attempt。新 attempt 必须重新编译并重新生成，不使用旧正文、旧诊断或验收答案作改写素材。获得一个可提交作者的完整章、三个 attempt 全部失败、无法满足隔离，或出现需作者决定的重大设定冲突时停止，不无限循环、不降低标准。

## 8. 记录

保存 `run_id`、日期、base commit、测试章计划、逻辑事件范围、协议/模型版本、全部冻结包和正文哈希、独立上下文凭据、汉字数、R/F 结论、隔离资格、作者结论及失效传播。失败正文保留为历史证据，但不得进入后续生成输入。测试通过前，第一卷正文仍为 `UNBUILT`。
