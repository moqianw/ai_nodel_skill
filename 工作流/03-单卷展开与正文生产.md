# 单卷展开、场景执行编译与正文生产

## 1. 两条入口与共同执行链

正文执行不新增第四设计阶段，但必须区分正式连续生产与完整正文环境测试两条入口。

### 1.1 正式连续正文

`VALID 单卷设计 → 卷级场景地图 → 3—5章滚动计划 → 当前章基础状态 → 场景编译器`

场景地图只保存跨场景有价值的功能、进入状态、主要变化、信息释放、离开状态和前后关系；临时站位、微动作和对白前提不永久写入地图。滚动计划是 `SOFT` 方案，可随真实章界调整。

### 1.2 完整正文环境测试

`连续 VALID 正式事件 + 测试专用章计划 + 必要正式依赖 → 场景编译器`

正文测试允许 `场景地图版本 = N/A`、`连续生产滚动计划版本 = N/A`，也不要求先建立整卷地图；但必须建立本次测试专用章计划，使用足以构成完整物理章的连续正式逻辑事件与正常正式依赖，不能绕过执行编译、生成许可、冻结场景包、独立 B/B2、冻结章节组装包、独立章节组装、整章读者盲读和事实验收。最终 `CHAPTER_DRAFT` 正文不少于 5000 个汉字；自然内容不足时重编章界，不得注水。旧中性自由校准、VQ-A/VQ-B 和 T01—T08 单事件/短场景测试不再作为入口，旧短测 Oracle 不进入新测试。

### 1.3 汇合后的强制链

正式连续正文与完整正文环境测试在场景编译器汇合，并共同执行到 B2 场景稿：

`场景编译器 → 生成许可 → FROZEN 场景单元 → 密封初稿生成器 → RAW_DRAFT → B2 有事实边界的叙事结构编辑器 → DRAFT`

随后共同进入整章链，再在状态提交处分流：

- 完整正文环境测试：`DRAFT 登记为 SCENE_DRAFT → 测试章节组装包 → 独立章节组装器 → CHAPTER_DRAFT（≥5000 汉字）→ 整章独立读者/盲还原 → 比较与四层审计 → 作者判断 → 结果记录`；
- 正式连续正文：`DRAFT 登记为 SCENE_DRAFT → 章节组装包 → 独立章节组装器 → CHAPTER_DRAFT → 整章盲状态还原 → 比较与四层审计 → 状态提交事务 → VALID`。

正式正文、续写和完整正文环境测试都执行到整章独立验收；**完整正文环境测试在结果记录后结束，不提交正式章节状态增量，也不把测试正文标为 `VALID`**。状态增量、快照和 `VALID` 只属于正式连续正文。短场景、换场景或独立人物片段可以用于内部诊断，但不能登记为当前正文测试。

## 2. 三个主职责、独立整编子角色与上下文边界

完整工作流文件是编译和审计规范，不是正文生成器每次写作时的上下文。每轮场景执行至少建立场景编译、初稿生成、语言整编、独立桥接核对四个互相隔离的执行上下文；正式物理章和完整正文环境测试都另开章节组装和整章验收上下文。测试控制器另行保管测试专用章计划和比较材料。不能用同一模型上下文自称第二遍独立整编，也不能用场景 B2 冒充整章组装。

仓库级“开始工作前”读取顺序只由控制器/编译器执行。密封初稿生成器、B2 叙事结构编辑器和盲还原器不得自行浏览仓库，也不得因通用启动规则重新加载项目状态、总索引或正式资料；它们分别以本节列出的显式输入作为完整上下文边界。

### 2.1 场景编译器

编译器负责读取和裁剪资料：

- 项目状态与短版[正文运行时协议](08-正文运行时协议.md)；
- 当前任务相关的 `VALID` 人物、事件、机制、现实、知情与保密资料；
- 连续生产时的场景地图、滚动计划、最新状态快照、必要状态增量和前一 `VALID/PUBLISHED` 正文；
- 完整正文环境测试时的测试专用章计划；
- 项目文风基线中本场必要的片段。
- 当前 `VALID` 的正文声音模型、叙事决策模型、本场功能路由，以及从 PDM 裁剪并完整展开的 `NARRATIVE_DECISION_CARD`；正式正文/回归另需已通过资格的声音胶囊。

编译器可以在流程建立、协议改变、故障诊断或专项审计时读取完整 `03 / 04 / 06 / 07`；普通逐章运行优先读取短运行时协议，不把完整工作流反复注入写作上下文。

编译器的唯一正文侧输出是自足的冻结写作包。包中的关键约束必须展开为可执行内容，不能只给文件链接后要求正文生成器继续读完整资料。

### 2.2 密封初稿生成器

初稿生成器的密封输入必须把“生成器运行头”放在最前面；运行头由编译器从固定协议生成，不携带剧情答案，只规定输入边界及初稿输出。初稿生成器只接收：

1. 状态为 `FROZEN` 且依赖仍有效的当前写作包；
2. 包中已经摘取的项目声音胶囊、本场叙事决策卡与文风必要片段；
3. 包中已经摘取或单独密封附带的必要前文。

初稿生成器只负责在事实、因果、人物与现场成立的前提下写出完整 `RAW_DRAFT`，不得返回部分正文或验收报告。内部自检可以存在，但**不能把同一上下文声称完成的第二遍当成独立语言整编或质量通过证据**。

### 2.3 B2 有事实边界的小说叙事结构编辑器（生成侧、Oracle 之前）

在新上下文中整编；只接收本次 `RAW_DRAFT`、对应未更改的 `FROZEN` 包和 `package_id`。不得接收 oracle、历史失败文本、旧 attempt 的验收意见、编译内部推理或完整仓库文件。

B2 是**有事实边界的小说叙事结构编辑器**，不是保守语言润色器。`RAW_DRAFT` 是可重构的叙事素材，不是必须逐句、逐段、逐动作保留的合同；`FROZEN` 包才规定本场必须成立的边界。B2 可以重定叙事焦点，重新决定哪些过程详写、略写或省略，重组段落与局部呈现顺序，并改变篇幅和收束位置。目标是让读者自然经历场景，而不是让最终稿忠实展示初稿如何完成检查清单。

B2 必须先把输入分为三层，但不输出清单：

1. **锁定层**：FROZEN 中的必须完成/不得提前完成、支撑关键判断的必要事实与证据、人物知道/相信/怀疑的边界、重要判断首次成立的相对时机、主要行为因果、关键对白前提、关系/情绪的必要变化、关键物体状态与离开状态；
2. **可重构层**：普通动作的表现数量与细度、非关键观察顺序、环境落点、心理措辞、段落边界、过渡、重复验证的展开程度、篇幅和结束句；
3. **可删除层**：无信息增量的复查、为了展示人物认真而存在的微步骤、已经由动作成立后的解释、重复结论、静态环境陈列、缺少当场动机且不属于离开状态的收尾动作。

锁定的是**叙事事实与认知因果**，不是 RAW_DRAFT 的全部叙述过程。B2 不得删除使关键判断成立所必需的证据，不得颠倒真实时间—因果顺序，不得改变认知上限、把不确定写成确定、把未完成写成完成或新增包外事实；但可以删除非必要普通动作，压缩多个同功能检查，合并重复观察与心理，移动不影响因果的局部信息，并让场景在最后一个有效动作、选择或余波处提前结束。

整编器在内部依次完成**锁定边界 → 判断叙事发动机 → 重新分配详略 → 整场重写 → 最终稿独立顺读**：

1. 以 FROZEN 为主建立锁定层；再读 RAW_DRAFT，识别其中哪些具体动作/证据已经成为关键因果的一部分，哪些只是同功能展开。RAW_DRAFT 中包外、无必要或自相矛盾的细节不因已经写出就自动获得保留权。
2. 确定本场真正的叙事发动机：人物此刻最想解决什么、哪一个未知或关系压力推动注意移动、哪次结果真正改变了下一步。以此重新分配详略，不按初稿步骤平均用力。
3. 对整场进行结构性重写。允许合并、压缩、删除或改换普通动作与环境承载方式；允许把解释改为动作后果或不写；允许删去无动机的尾部折返并在更早的具体动作处结束。合并只适用于读者无需重新定位对象、压力、时间、空间、任务、行动权或叙述声音的持续因果脉冲；不能仅删除换行，把实际发生重定位的内容粘成长段。局部观察、判断与紧接行动可以同段完成，共同大目标也不能掩盖真实切换。局部呈现可以重排，但真实发生顺序和关键认知形成顺序不可颠倒。
4. 检查远距离的**跨段重复**。对已经成立的结论，若后文只换措辞再解释且不产生新证据、判断修正、真实心理波动或行动选择，删除纯复述；复现若属于锁定因果，只保留使它发生并产生结果所需的叙述，不保留整套检查仪式。
5. 脱离 RAW_DRAFT 的句序，**只沿最终 DRAFT 顺读**：先为每段辨认主要叙述承载者和主语序列，确认同一人物的连续观察/动作没有被静物、工具、身体部位或环境无功能地反复抢走句首中心；每次换主语必须对应真实的行动权、感知来源、受力反馈、对话主导或任务转移，并由前句引出。再逐段核对“前段末尾活跃中心 → 本段第一指称”：段首“他 / 她 / 它”只有在紧邻前段仍由同一唯一承载者持续行动/感知、时空/任务/互动主导没有重置且没有竞争先行词时才可继承；场景、小节、换时空、换任务、换行动权/对话主导或多人歧义后必须重新点名。随后核对人物状态变化是否有具体可见偏差并由后续回应/动作接收；没有变化时不按配额补神态。再逐处核对转折是否存在真实前后差异，环境/物件/感官/姿态描写是否承担定位、阻力、反馈、人物状态、关系、判断/行动变化或持续气氛；删除后这些作用均不变的内容删去、并入动作或重写。最后确认叙事焦点连续、详略有主次、人物没有为每个决定解释原因，收束没有再次总结；逐段确认读者是否仍处于同一对象、压力、时间、空间、任务、行动权与叙述声音形成的因果脉冲。需要重新定位时应自然分段或重组；局部结果只改变手中动作、却没有改变当前压力时，不强制拆段。同时核对关键人物/物体的前后状态、动作可达性、必要证据、认知边界与离开状态。普通且唯一合理的日常取放可以省略；若只能新增事实或改变锁定层才能修复，返回 `EDIT_BLOCKED`。

以上步骤只是内部编辑方法，不要求在正文里列问题，也不规定成品必须变短。删减、扩写、重排都只服务叙事；不能靠一律合并段落、删除心理或压缩字数来“达标”，也不能用固定字数把长段机械切短。段落长短是结果，判断依据是内部是否仍由同一叙事动作统领。**不要求每件日常物品的每次取放都显式写出**：若取放可以由普通读者唯一合理地补足，且不影响行动可达性、风险、证据或关键离开状态，可自然省略；若同一物体在同一连续行动里出现互不兼容、无法可靠推断的持有/位置状态，必须修复或阻塞。

**段落边界强制复核（B2 内部执行，不输出分析）**：为终稿每段辨认当前对象、压力、时间、空间、任务、行动权与叙述声音，并检查读者是否需要在段内重新建立其中任一项。观察、判断与紧接的动作即使产生局部结果，只要仍受同一压力牵引，可以连续；一旦转入新的对象、处置任务、时间层、空间位置、互动主导或独立背景/回忆块，原则上用段界承接，或删冗重组。**共同总体目标不能证明无需分段，局部结果成立也不能证明必须分段**。不凭段长、句长、同一主语或段数作判断；若顺读可明确指出误分或漏分，B2 必须实际重写。

**叙事接缝强制复核（先于段落负载）**：凡相邻句、对白或段落发生主语、注意对象、行动权、叙述方式或局部任务变化，终稿必须让读者从文本本身辨认继续、反应、打断/抢先、结果—选择、联想回落或明确省略跳转。前后谈论同一对象、被放进同一自然段，或出现“于是/然后/这时”等连接词，都不能单独证明承接成立。对白必须接得上它回应、回避、准备或打断的现场，并由后续话语、动作或沉默接收。接缝不成立时须删冗、重排或重写，不能只移动换行。

**段内叙述主轴强制复核（先于逐缝解释）**：每段先确定主要承担感知、动作、心理或关系压力的人物。同一人物仍在连续行动时，优先保持其显式或承前省略的主语，把物体和环境写成其感知/操作/反馈对象；不得为了变换句式形成无功能的 `人物 → 物体 → 人物` 或 `A → B → A` 主语摆动。主语只有在行动权、感知来源、外力反馈、对话主导或任务真实转移时切换，并须由前句引出。主语稳定不等于句句重复人名/代词，也不禁止真正改变局面的物体反馈。

**段首指代落点强制复核（与段内主轴分立）**：每个自然段检查第一处人物/物体指称。裸“他 / 她 / 它”或省略主语只有在紧邻前段的唯一活跃承载者可无歧义继承、且时间/空间/任务/感知链/互动主导未重置时成立。场景或小节开头、时间/空间跳转、新任务、行动权/对话主导变化、外力插入、回忆回落、多人同场存在竞争先行词时，必须用姓名、唯一身份/角色或明确物体名称重新落点。前文曾提及不等于仍可继承；读者需要回读即为失败。

**人物可见表层强制复核**：当人物关系位置、压力、犹豫、警觉、体面或用力方式发生变化时，终稿须有一项相对当场常态的具体可见偏差，并由另一人物、人物下一动作或读者判断接收。可落在目光、声音、呼吸、姿态、速度、手部紧张、未完成动作或面部变化；不设神态数量指标，没有变化时不强加，已经可见时不再解释含义。

**转折与描写功能强制复核**：转折词必须对应预期—结果、意图—反馈、表面—关系或前后状态的真实差异。环境、物件、感官与姿态描写须承担定位/可达性、阻力/资源、反馈、人物状态、关系压力、判断/行动变化或持续气氛中的至少一项，并由后文接收。删除后这些作用均不受影响的内容默认删去或并入有效动作。

整编器只输出相同 `package_id` 和完整最终 `DRAFT`，不输出 `RAW_DRAFT`、删改说明、检查清单、规则解释或 PASS/FAIL。控制器单独保存最低限度的初稿/整编上下文区分凭据与交付顺序；该凭据不是正文、不得给盲还原器，也不是整编质量通过的自证。独立验收器仅对该最终 `DRAFT` 盲还原；原始 `RAW_DRAFT` 不交给验收器，也不参与同一 attempt 的改稿循环。

生成器不得读取：

- 完整 `03 / 04 / 06 / 07 / 08`；
- 完整人物、单卷、机制或有效记录；
- 回归 oracle、历史故障清单或上一份失败测试正文；
- 场景编译过程中的内部推理；
- 与当前章无关的全书资料。

初稿生成器发现包内矛盾或缺失时停止并返回编译器，不得自行打开上游文件补设定。初稿的输出只有完整 `RAW_DRAFT` 和 `package_id`；之后由 B2 叙事结构编辑器输出最终 `DRAFT`。

### 2.4 独立验收器

验收分两段，顺序不可反转：

1. **盲还原**：新上下文不得接收写作包、`RAW_DRAFT`、剧情资料、比较材料或生成推理。正式连续正文与完整正文环境测试都只接收“上一章读者可见必要末尾（卷首为 N/A）+ 完整 `CHAPTER_DRAFT`”，不得接收状态快照或后台摘要。先冻结一份“读者仅凭已读正文实际能恢复什么”的整章还原结果。
2. **比较验收**：再向验收器提供冻结写作包、验收协议和盲还原结果；回归测试此时才可提供验收 oracle。验收器比较正文实际表达与预期状态，再运行四层审计。

正文级回归、高风险章节、重要机制首次展示、重大关系转折和复杂空间/机械场景必须使用独立上下文验收。若环境无法建立新上下文，只能标为普通内部复核，不能宣称完成严格盲验或正文级回归。

## 3. 正文初始化、场景地图与滚动计划

项目第一次进入正文、作者指出系统性文风问题、叙事策略重大变化或更换模型后明显漂移时，刷新项目文风基线与运行时协议。初始化只负责叙事接口，不把人物、机制或具体失败案例堆入文风。

当连续两个以上完整章 attempt 的事实/因果基本成立、但作者仍因整体模型腔否定全部正文时，暂停继续抽取候选，先从正式测试正文定位负责层并刷新声音模型、PDM、决策卡编译、B2 或章节组装协议。修复后用新的完整章包和全新隔离上下文重测；不得回到中性自由校准、VQ 夹具或单事件短测绕开完整剧情和章节压力。

正式连续生产前建立卷级场景地图；每个场景只保存：

- 场景功能；
- 进入状态；
- 主要变化；
- 信息释放、隐藏或误导；
- 离开状态；
- 与前后场景关系。

未来3—5章滚动计划记录每章承接场景、章首承接、核心问题、读者获得、章末落点、下一章推动、目标字数与章界调整条件。正式连续生产的物理章默认以约2500字为规划目标，2200—3000字只作为密度复核信号，不是硬切线或填充指标。完整正文环境测试可以把卷级地图与连续生产滚动计划记为 `N/A`，但必须另有冻结的测试专用章计划；测试 `CHAPTER_DRAFT` 硬下限为 5000 个汉字。

### 3.1 完整章节与跨章执行

多场景物理章使用[完整章节组装与连续生产](09-完整章节组装与连续生产.md)：各场景按依赖顺序独立生成并形成只在章内有效的临时状态；全部场景达到 `SCENE_READY` 后冻结章节组装包，再由新的独立章节组装器输出唯一 `CHAPTER_DRAFT`。场景稿不能分别提交正式状态，下一章也不能依赖尚未通过整章验收的临时结果。

整章通过后，以 `PREPARED → COMMITTED` 事务同时提交章节增量、最新快照、验收记录、物理章映射和运行台账；成功后才标为 `VALID` 并允许下一章冻结首个场景包。

新协议 `NSQ-2026-10-08.1` 要求在事实编译之外裁剪少量 `reader_value / foreground_choice / human_latitude / continuity_load_bearing / compress_permission` 叙事决策，防止把逻辑状态机直接展开成操作记录；具体见 [`10-读者体验与假阳性防护.md`](10-读者体验与假阳性防护.md)。

## 4. 场景执行编译

编译器把当前 `VALID` 资料编译为只对本场有效的执行状态。简单场景可以很短，复杂场景按风险增加内容；不得复制整个设定库。

### 4.1 场景事实状态

- 时间与地点；
- 当前在场人物及身体状态；
- 重要物品和实际影响行动的环境物体；
- 当前现实条件与超凡规则状态；
- 本场不能改变的事实；
- 本场不能提前泄漏的未来信息。

### 4.2 人物认知状态

对每个重要参与者分别列出：

- 客观知道；
- 当前相信；
- 当前误解；
- 当前怀疑；
- 当前不知道；
- 主动隐瞒；
- 作者知道但该人物本场绝对不能使用的信息。

“知道”与“相信”不得合并，读者信息不得反灌给人物。

### 4.3 即时目标与行为约束

对每个重要参与者明确：

- 进入本场时正在做什么；
- 当前直接目标；
- 信息、关系、事实、结构、风险或情绪中的优先注意对象；
- 当前风险、边界和顾虑；
- 停止当前行为的条件；
- 改变目标所需的新证据或关系变化。

人物画像提供信息优先级和边界，不提供固定“先 A、再 B、再 C”程序。具体动作顺序必须由本场证据和空间状态生成。

### 4.4 空间与物体状态

涉及走动、接触、拿取、机械测试、滴落、遮挡、多人物站位、门窗、桌面物体、追逐或近距离互动时，至少明确：

- 人在哪里，坐或站，面向哪里；
- 手上有什么；
- 关键物体在哪里；
- 人与物的大致距离；
- 门窗、障碍、光源和通道状态；
- 下一动作能否从当前位置直接完成。

### 4.5 动作因果链

对机械操作、异常验证、风险处理、制度流程和陌生人互动等关键动作，确认：

`为什么行动 → 实际怎样完成 → 得到什么可观察结果 → 结果为什么触发下一步`

无法确认的专业细节采用保守写法；任一步只能用“剧情需要”解释时不得进入写作包。

### 4.6 对白前提链

对关键发言确认：

- 谁说、对谁说；
- 回应哪个已出现信息；
- 为什么现在说；
- 依赖前提是否已出现；
- 对方为什么回应；
- 发言者、指代和制度指令对象是否明确；
- 是否为了作者解释而制造问答。

角色提问必须来自真实信息缺口、关系目的或行动需求；现场已有显然答案时不得只为启动对白而发问。这里只编译功能和前提，不预写最终台词。

## 5. 正文生成许可

只有以下项目全部通过，编译器才可冻结写作包：

- 人物认知无越权；
- 行为有当场动机和停止条件；
- 空间状态允许计划动作发生；
- 关键动作链在现实与机制上成立；
- 关键对白前提完整；
- 未来信息和作者后台知识已隔离；
- 不存在需要作者决定的阻塞性 `HARD` 缺口；
- 包内已包含生成器实际需要的文风片段和前文，不要求生成器下钻资料。
- 正式正文或正文测试必须绑定当前生成模型记录、声音模型/胶囊、PDM/决策卡、运行协议与 B2 协议；不再要求 `VOICE_QUALIFIED` 或同性质中性资格记录。

任一项失败时补正式资料、调整局部实现或提出最小补问；不得以含糊正文掩盖。

## 6. 冻结写作包、版本与失效

### 6.1 包状态

- `ASSEMBLING`：编译中，不得生成；
- `FROZEN`：许可通过、内容与依赖向量锁定，可供一次或多次同依赖返修生成；
- `STALE`：任一直接依赖变化，不得继续生成或返修；
- `SUPERSEDED`：已有新包替代，只供追溯。

生成前写作包一旦冻结，正文生成器和验收器不得修改。需要改变场景状态、人物认知、动作链或对白前提时，旧包标为 `SUPERSEDED`，由编译器生成新版本。

### 6.2 必须记录的依赖向量

每个包至少记录：

- `package_id` 与包版本；
- `base_commit`；工作区存在未提交依赖时，还要记录相关文件内容哈希；
- 正文运行时协议版本；
- B2 叙事结构编辑协议版本；
- 每个直接正式资料的路径与版本/内容哈希；
- 当前正文状态快照版本；
- 前一 `VALID/PUBLISHED` 章的版本；
- 当前物理章计划版本与 `CAP` 协议版本；
- 场景地图版本，独立测试为 `N/A`；
- 滚动计划版本，独立测试为 `N/A`；
- 测试专用章计划版本；正式连续正文为 `N/A`；
- 正文声音模型版本、声音胶囊哈希、叙事决策模型版本、本场决策卡哈希与生成模型/B2 协议资格记录或 `N/A`；
- 文风片段与必要前文的来源版本；
- 冻结时间与生成许可结果。

### 6.3 自动失效

任一直接依赖在冻结后发生变化，包自动 `STALE`。典型情况包括人物资料修改、前章返修导致认知/物品变化、状态快照推进、场景地图或滚动计划改版、机制规则变更、正文声音模型/声音胶囊/PDM/决策卡编译/生成模型资格变化、B2 叙事结构编辑协议变化、文风必要片段变化。

正文生成器启动前、返修重跑前都必须核对依赖向量。由 `STALE` 包生成的文本自动无效，不进入验收。只修改正文措辞且包内事实/因果未变时，可沿用同一 `FROZEN` 包；一旦返修需要改变执行状态，必须重新编译。

## 7. 冻结写作包内容

包必须自足且只含当前场景实际约束。为提高执行优先级，正文生成器实际收到的包按“生成器运行头 → 当前场景执行状态 → 本场叙事决策卡 → 项目声音胶囊 → 文风执行摘要 → 必要前文 → 依赖追溯信息”的顺序组装；依赖哈希等审计字段可以留在包尾，不要让长元数据把生成约束挤到上下文前部。

### 7.1 密封生成器运行头

每个 `FROZEN` 包必须包含一段短运行头，并原样放在正文生成器输入最前部。运行头至少写明：

- 只允许使用当前冻结包及密封前文，不得自行补读仓库或外部项目资料；
- 先生成完整 `RAW_DRAFT`，交给**另一全新上下文**的 B2 叙事结构编辑器；不能在本上下文自称完成独立第二遍；
- **普通连续过程硬门槛**：同一动作/观察/判断链若连续出现三个及以上单句段，默认视为结构风险；除非每个单句都承担明确不同的停顿、突变或转场功能，否则在输出前通过删冗、重排、补足自然承接或按真实功能重新分段来修复。禁止只删除段落边界，把多个已完成步骤、不同注意对象、阶段结论和后续计划粘成一个长段；
- **叙事接缝硬门槛**：主语、注意对象、行动权、叙述方式或局部任务变化处必须存在可读承接；相关信息并置、同段放置或万能连接词不能代替继续/反应/打断/结果/联想回落/明确跳转；
- **段内叙述主轴硬门槛**：同一人物持续观察、行动或思考时，优先维持该人物作为显式或承前省略的主语；不要让静物、工具、身体部位和环境无功能地轮流抢占句首。每次主语切换必须对应真实的行动权、感知来源、受力反馈、对话主导或任务转移；
- **段首指代落点硬门槛**：每段第一处“他 / 她 / 它”或省略主语必须能由紧邻前段的唯一活跃承载者直接恢复；场景/小节开头、重定位、行动权/对话主导变化或竞争先行词出现后，必须重新点名；
- **人物可见表层硬门槛**：状态或关系压力已改变时，不能只有任务动作、对白信息和后台结论，须有被后续接收的具体表层偏差；没有变化时不得按数量强加神态；
- **转折/描写功能硬门槛**：转折必须有真实前后差异；描写必须改变定位、阻力、反馈、人物状态、关系、判断/动作或持续气氛，删除后无损的装饰内容须删改；
- **重复结论硬门槛**：同一结论已经由动作、观察或一次必要心理判断成立后，不得在后续复现、录像、回看或场景尾部再次完整抽象总结；后续只能写新增变量、新证据、结论变化或该结论实际导致的选择；
- 门槛由 B2 在完整文本中执行，不输出检查表，也不把规则写进正文；初稿生成器可以自检，但不能跳过 B2。

这些是跨场景的生成输出门槛，不是 T05 专用写法，也不是固定段落模板。

### 7.2 场景包主体

包主体至少包含：

- 任务类型：正式连续正文 / 完整正文环境测试；
- 逻辑事件与场景目标；
- 必须完成与不得提前完成；
- 场景事实与禁止信息；
- 参与人物的认知差、即时目标、信息优先级和停止条件；
- 空间与物体初始状态；
- 关键动作因果链；
- 关键对白前提；
- 读者信息与当前悬念；
- 当前正文声音模型与叙事决策模型版本、本场功能路由、完整展开的 `NARRATIVE_DECISION_CARD` 与裁剪后的短声音胶囊；不得附成熟作品全文、作品名、抽样分析或可识别原句；
- 决策卡必须包含 `subject_anchor`：各段主要叙述承载者、允许主语转移的真实节点及应避免的无功能主语摆动；`paragraph_entry_anchor`：可强连续继承代词的段首、必须重新点名的重定位与可能竞争的先行词；`character_surface`：当场常态、必须可见的状态偏差、感知者与接收动作，无变化时明确不强加神态；`prose_function`：本场有效描写/持续气氛、真实转折点与应抑制的无功能装饰；不得预写具体句子；
- 本场必要的文风片段；
- **生成侧文风执行摘要**：至少把与当前场景直接相关的持续因果脉冲、读者重新定位点、心理/判断停止条件、同义复述控制、场景尾部总结边界展开成可执行短约束；验证/推理场景还必须明确“规则第一次形成时允许必要判断，后续复现只写新增变量、新证据或结论变化，不把同一规则反复总结成小报告”；
- 必要前文原文或精确摘录；
- 本场高风险提示，但不包含回归 oracle 的标准答案；
- **B2 锁定边界**：只列必须在最终 DRAFT 守恒的关键事实/证据、认知边界及关键判断形成时机、主要因果、对白前提、关键物体与离开状态；不得把全部普通动作、检查次数或原稿式叙述步骤误列为锁定项；
- 生成许可与依赖向量。

一个章节包含多个差异明显的场景时，使用同一章计划下的多个冻结场景单元；不能把全章所有资料无选择堆进同一长包。场景单元全部就绪后另冻章节组装包，按 `09` 由独立章节组装器形成整章，而不是直接拼接。

## 8. 初稿生成与 B2 叙事结构整编的输出

初稿生成器核对包状态与 `package_id` 后，只根据密封输入输出完整 `RAW_DRAFT`；另开 B2 上下文读取同一 FROZEN 包和该 `RAW_DRAFT`，在锁定事实与认知因果的边界内重新决定叙事详略、结构、段落与收束后输出最终 `DRAFT`。**缺少独立整编阶段时只能算非严格试写，不得计为严格正文级回归通过**。输出边界：

- `package_id`；
- 初稿：`RAW_DRAFT`；整编器：最终 `DRAFT`；
- 包矛盾或不足返回 `COMPILE_BLOCKED`；整编无法在锁定事实与因果内完成返回 `EDIT_BLOCKED`，不得自行补设定。

两个生成侧上下文均不输出场景编译表、内部推理、检查表或验收结论，也不因后续计划添加包外铺垫。B2 必须对叙事发动机、详略、段内叙述主轴、段首指代落点、人物可见表层、转折/描写功能、叙事接缝、跨段功能重复、段落组织和收束进行整场处理，而非只改可见短句；RAW_DRAFT 的句序、动作密度和字数不构成保留义务。最终内部检查须**以最终稿本身为输入**重新顺读一次：先标出每段主要叙述承载者和主语序列，修复无功能的频繁换轴；再检查每段第一指称能否由紧邻前文唯一恢复，不能时重新点名；随后检查人物状态变化是否有被后续接收的具体可见偏差，转折是否有真实差异，描写是否承担并持续发挥作用；再检查真正的主语、注意对象、行动权、叙述方式或局部任务变化处是否有可读承接；之后看段落功能与信息是否重复，检查是否为了反碎片化而把多个完整节拍盲目并入同一长段，最后看人物/关键物体的时间与空间轨迹。不要把“原稿里也这么写”当成最终稿逻辑成立的证据。不得机械拼接相关或不相关的信息块，也不得改变写作包锁定层或增添新的剧情结论。

## 9. 盲还原与比较验收

### 9.1 盲还原

验收器在未见写作包时冻结盲还原。正式连续正文与完整正文环境测试都根据“章节组装包冻结时确定的上一章读者可见必要末尾（卷首为 N/A）+ 完整 `CHAPTER_DRAFT`”还原，前文只提供普通读者已经读过的信息，不提供后台状态或设计答案：

- 人物位置与姿态变化；
- 重要物体位置变化；
- 每个人新知道、相信、怀疑或误解了什么；
- 每个关键动作的文本内触发；
- 每句关键对白回应的文本内前提；
- 场景结束时关系、情绪与目标实际发生的变化；
- 无法从读者可见材料确定、只能猜测的空白。

盲还原一旦完成不得在看到写作包后回填或改写。

### 9.2 比较验收

再提供冻结包与验收协议，逐项比较。以下情况直接失败：

- 正文使用生成前不存在、现场也未产生的前提；
- 人物知道不应知道的信息；
- 关键动作无法从正文前一步推出；
- 影响当前因果理解、后续连续性或必须传达给读者的空间/物体状态无法从读者可见材料连续还原；但仅有可唯一合理补足、对事件与阅读理解无影响的日常取放省略，不应仅因没有逐字写出而判成事实连续性失败；
- 对白需要验收器借助写作包替正文补前提；
- 角色询问现场已有显然答案的问题；
- 行为只能用“为了推进剧情”解释；
- 正文新增未经上位资料允许的长期人物特质、机制或现实条件。

失败时重写整条问题链，不能只替换词语。

## 10. 四层审计与返修

比较验收通过后继续：

1. **事实与连续性**：时间、位置、身体、物品、知情、规则和前文承诺；
2. **因果与人物**：目标、阻力、选择和反应是否来自当时认知；
3. **叙事与人物声音**：视角、心理、人物执行倾向与信息边界；
4. **语言、AI味与重复**：句段、通用反应、总结腔、对白后解释、相似章末和近期同构。

事实、因果或前提失败时退回执行链；上层成立后才做语言润色。正式正文允许在同一 `FROZEN` 包下做不改变事实、认知、动作链、对白前提和离开状态的受控语言返修，但返修指令只能描述正文可观察的问题与允许保持不变的边界，不能注入生成器原本不可见的后台答案；一旦需要改变执行状态，旧包必须 `SUPERSEDED` 并重新编译。高风险章节返修后重新进行独立盲还原。

严格冷启动回归采用“一次 attempt 一次判定”：验收器读取 oracle 后若判 `FAIL`，本 attempt 立即结束，不能把 oracle 或由 oracle 推出的标准答案反馈给原生成器现场改到 `PASS`。若故障需要修改仓库、文风片段或冻结包，先完成负责层修复，使旧包 `STALE/SUPERSEDED`，再用全新上下文开启新的 attempt。

## 11. 正文状态、快照与章节增量

正文状态区分：

- `DRAFT`：使用有效冻结包生成，但尚未通过验收；
- `VALID`：通过盲还原比较、四层审计，且章节状态增量与最新快照均已成功提交；
- `PUBLISHED`：已对外发布，修改时检查全部依赖正文。

### 11.1 当前状态快照

每卷维护一个最新状态投影，保存当前时间、位置、身体、物品、关系微状态、人物认知、读者信息、规则展示和近期重复窗口。快照有单调递增的 `state_version`，不承担完整历史。

### 11.2 每章状态增量日志

每章变为 `VALID` 时追加不可覆盖的增量记录：

- `delta_id`、章节版本、所用 `package_id`；
- `previous_state_version` 与提交后的 `new_state_version`；
- 本章新增、修改、结束的状态；
- 新建、推进、回收或失效的悬念；
- 关系微状态和人物认知变化；
- 新增/移动/损坏的重要物品；
- 已知直接依赖这些变化的后续章节或场景；
- 是否触发上位事实审计。

状态快照是增量日志的最新投影。整章提交按 `09` 的 `PREPARED → COMMITTED` 事务执行，任一组成文件失败时快照不得前移。每3—5章形成 checkpoint，记录覆盖的增量范围与投影版本。

### 11.3 回改传播

修改旧章时，从该章原增量开始比较新旧差异，识别直接依赖它的后续增量、冻结写作包和章节。受影响对象标为待重审或 `STALE`，从最早真实依赖点重新投影；不依赖该变化的后文无需机械全部推倒。

## 12. 作者反馈路由

- 单场前提或动作错误：修正文/场景包，必要时登记回归故障；
- 稳定人物错误：修人物执行画像，并区分作者确认与可靠推导；
- 机制/现实错误：修对应正式负责文件；
- 跨人物、跨场景的叙事错误：修文风基线；
- 规则存在但未进入冻结包：修编译器/包组装；规则已明确进入冻结包、同一上下文自检仍持续失效：检查是否真正使用**B2 有事实边界的叙事结构编辑器**，以及写作包是否误把原稿全部过程锁死；必要时修生成/整编职责与质检边界，不再向人物卡或文风基线重复添加同义规则；

同类错误在两个及以上不同性质场景复发时，优先审计执行协议，不继续堆局部禁令。

## 13. 展示边界与最低验收

编译状态、冻结包、盲还原和比较表默认属于内部执行。用户正常要求写章时主要收到正文；只有作者要求审计、出现阻塞、验收失败需说明或用户要求查看执行包时才展示。

正文进入 `VALID` 前至少满足：

- 写作包在生成时为 `FROZEN` 且依赖有效；
- 生成器上下文没有完整工作流、完整资料或回归 oracle；
- 盲还原在看到写作包前已经冻结；正式连续正文的盲还原只可额外读取冻结时确定的读者可见必要前文；
- 人物认知、空间、动作和对白可从读者可见材料连续还原；
- 关键变化正面发生，未来信息与后台规则未越权；
- 四层审计通过；
- 多场景章节已经过独立章节组装与整章统一验收，场景稿未被直接拼接冒充完整章；
- 章节状态增量已追加，最新快照与 checkpoint 规则保持一致；完成这些提交后才标记 `VALID`。
