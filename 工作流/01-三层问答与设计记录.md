# 三层问答、覆盖控制与完整记录

## 1. 适用范围

小说基础模型、全书架构、单卷设计都使用本算法。目标不是用尽可能少的问题快速得到一个骨架，而是在不重复已有结论的前提下，把当前阶段真正需要处理的方面问全。

三层问答是阶段内部的讨论顺序；阶段覆盖表是完整性控制。二者必须同时使用，不能因为三层已经走完就默认覆盖充分，也不能把覆盖表机械变成逐栏填空。

一次阶段问答应当是一段连续对话。Web Chat 负责提问、确认作者每轮回答和维持覆盖账本；阶段结束时不再生成压缩总结。当前实际交接通常只保存 Web Chat 输出：一条输出先处理上一轮作者回答，再提出下一轮问题，作者回答本身发生在两条输出之间而不在文件中。项目 Agent 必须据此区分作者决定回显、模型解释/推导与候选问题，分别生成编译证据与当前有效记录，再以有效记录作为正式资料的直接问答来源。

## 2. 开始前的输入

Web Chat 只需读取：

- 当前阶段目标；
- 当前 `PROJECT_ROOT/项目状态.md`（项目根目录由[项目路由](../项目路由.md)确定）；
- 与当前阶段直接相关的 `VALID` 文件；
- 需要重新审计的 `DIRTY` 文件；
- 作者指定或项目状态登记为候选来源的 `REFERENCE` 材料；
- 上一阶段的有效设计结果；
- 上游文件中明确登记的覆盖缺口与后置事项。

不要默认加载全部历史对话和全部旧正文。需要追溯时再沿链接读取。

目标阶段为 `UNBUILT` 时可以开始设计；为 `BLOCKED` 时先说明缺少哪个 `VALID` 上游，不提前采访后续内容。

Web Chat 可以根据作者过去明确选择推断偏好，用于排序方案、减少重复问题和提出更合适的选项；偏好推断不能冒充本轮作者确认，也不能替代阶段覆盖检查。

## 3. 继承候选预处理（重构项目）

继承候选预处理发生在三层问答之前，只用于减少重复确认，不构成新的设计阶段或第四层问答。

1. 只读取作者指定、或 `项目状态.md` 已登记为本轮候选来源的参考资料；不默认扫描全部旧正文。
2. 按主题汇总旧信息，并分成四类：
   - **明显仍需重新设计**：新版方向已经要求重做；
   - **与新版冲突**：不得继承，保留为历史；
   - **高概率可以直接继承**：稳定且与当前方向兼容，适合批量授权；
   - **低影响、可暂时继承**：不妨碍当前设计，允许先以暂定状态使用。
3. 先向作者展示简洁分类和例外项，再请求一次批量授权；姓名、基础家庭关系、稳定背景、普通生活习惯等不得拆成逐条重复提问。
4. 一般批量授权不能覆盖核心世界规则、核心人物本质、作品核心承诺或结局约束等 `HARD` 内容。它们需要当前明确授权，或由当前有效资料证明明确兼容。
5. Web Chat 必须在下一轮开头准确回显获准范围、暂用范围和排除项，使授权留在完整问答中。批量确认的项目通常为 `CONFIRMED + INHERITED`，暂时沿用的低影响内容通常为 `TENTATIVE + INHERITED`，并分别判断 `HARD / SOFT`。
6. 后续问答产生新版决定时，冲突继承项自动失效，不要求新版迁就旧资料。

本轮没有指定参考来源时跳过本节。

## 4. 阶段覆盖账本

### 4.1 使用原则

Web Chat 在对话内部维护覆盖账本。账本中的每个必要检查点必须处于以下一种状态：

- **已覆盖**：作者已经作出足够明确的决定；
- **已继承**：已经过本轮明确或批量授权；
- **可推导**：可由当前有效决定可靠推出，且已说明推导依据；
- **明确后置**：作者或阶段边界已明确留给哪个后续阶段；
- **不适用**：已说明为什么本项目不需要；
- **缺失**：尚未讨论，也不能安全推导或后置。

`缺失` 不能作为阶段停止状态。`明确后置` 也不能成为逃避提问的默认选项：如果一项会改变本阶段的核心方向、人物本质、规则闭环或下游可设计性，就必须在本阶段处理。

覆盖账本是内部控制，不要求阶段结束时由 Chat 输出总结。项目 Agent 会收到原始完整记录后重新独立审计一次，不能直接相信 Chat 声称“已经问全”；审计结果与仍有效的决定由 Agent 写入有效记录。

### 4.2 阶段一：小说基础模型覆盖表

至少检查以下方面：

1. **作品承诺与读者体验**：题材组合、核心卖点、主要阅读快感、日常与特殊内容的关系、情绪基调、叙事规模、明确不写什么。
2. **现实与世界前提**：时代和地域框架、现实社会运行基线、超凡是否唯一、社会认知边界、故事时间跨度、能力来源是否解释。
3. **核心机制完整链条**：资格、触发、形成过程、能力方向、强度、成本、成长、损伤、死亡、复制与重复、可见痕迹、证据与边界案例。
4. **意识与伦理**：若故事涉及非人主体则讨论其人格与责任；否则讨论本书能力的真实行为边界、人物自主权、隐私与伦理。
5. **男主开局模型**：年龄与生活阶段、家庭和资源、能力与技能、欲望与恐惧、优点与缺陷、行为倾向、持续行动动力、关键前史。
6. **每位核心角色开局模型**：独立目标、生活压力、家庭与资源、能力与缺陷、行为倾向、与主线的独立关系、第一次接触定位。
7. **核心关系网络**：每一对核心人物的起点、第一印象、吸引与冲突来源、信息差、边界、长期不可替代性；多角关系不得只设计男主分别与每个人的关系。
8. **开局与第一关键异常**：故事起点、第一件关键事件或独特机制表现为何发生、开局资源如何支撑、哪些细节留给阶段二或三。
9. **长期运行条件**：故事基本矛盾、持续制造事件的动力、数量与规模约束、家庭/学业/工作/经济线、普通人与异常的长期接触方式。
10. **秘密与社会反馈**：核心知情边界、证据形态、目击与传播上限、保密为何可持续、不能依赖哪些便利机制。
11. **终局约束**：时间落点、关系落点、世界状态、人物成长落点、必须保留与明确不锁死的部分。
12. **继承与排除**：旧资料哪些继承、暂用、冲突、拒绝或仍需重做。
13. **正文表现承诺**：视角原则、叙事距离、心理呈现、对白自然度、作者旁白介入程度、整体语言读感和明确不接受的表现方式。阶段一只确定全书级方向，不要求提前固定每个人的口癖或每章句式；可在首次正文初始化时用作者认可样本继续校准。

阶段一不必提前决定每卷剧情，但不能把“核心人物缺少独立生活目标”“关键机制没有代价或死亡边界”“终局保密没有可持续原因”等问题推给阶段二。

### 4.3 阶段二：全书架构覆盖表

至少检查以下方面：

1. 开篇状态、终局状态以及二者之间不可省略的变化；
2. 主因果链、阶段转折、关键选择、代价和不可逆结果；
3. 主角、每位核心人物及关键非人角色（如适用）或特殊机制的全书发展线；
4. 每一条核心人物关系的发展、冲突、修复和最终落点；
5. 世界规则与特殊机制的发现顺序、应用升级和风险升级；
6. 秘密、证据、知情者和社会反馈的全书变化；
7. 日常、校园/职业、家庭、经济和现实资源随时间的变化；
8. 长期伏笔、悬念、回收与信息释放顺序；
9. 时间推进、学期/假期/年龄节点和现实可行性；
10. 分卷边界与每卷的“目标—阻力—选择—代价—高潮—不可逆结果”；
11. 卷间因果：上一卷改变了什么，下一卷为何必须发生；
12. 强度、节奏和题材比例是否长期符合阶段一承诺；
13. 终局中心事件与各发展线如何在同一结局闭合；
14. 尚未解决的基础模型缺口是否会阻塞架构，是否需要反向修改上游。

不能只给每卷一句主题或事件名；每卷存在的因果必要性和不可逆结果必须明确。

### 4.4 阶段三：单卷设计覆盖表

至少检查以下方面：

1. 卷首状态、卷末状态和本卷不可逆变化；
2. 本卷核心目标、阻力、关键选择、代价与高潮；
3. 完整主事件因果链以及每个关键事件的进入/离开状态；
4. 支线和日常内容的独立价值、位置和对主线/人物的反馈；
5. 本卷涉及的每位核心人物与关键非人角色（如适用）或特殊机制的行动线；
6. 每条相关关系线和感情线的具体推进，不只写结论；
7. 特殊机制的展示、实验、限制、代价与现实后果；
8. 知情、误判、秘密、证据和信息释放的逐步变化；
9. 家庭、学业/工作、经济、时间、空间、物流、伤势和监控等现实可行性；
10. 伏笔的埋设、强化、延迟、回收和跨卷接口；
11. 日常/超凡、松弛/紧张、关系/事件的节奏分布；
12. 逻辑事件的拆分尺度是否足以让 Agent 继续展开场景；
13. 与前卷结果、后卷入口和 `VALID` 上游的连续性；
14. 是否出现为了保住局部剧情而需要反向修改上游的情况。
15. 本卷是否有不同于全书基线的正文表现要求：主视角切换、心理浓度、日常松紧、信息隐藏方式、特殊角色语言或必须避免的叙述习惯；没有则明确继承项目正文文风基线。

阶段三完成后仍由项目 Agent 自动展开逻辑事件、场景和正文；覆盖表不是重新增加“细纲问答层”。

阶段三的正式编译必须把每个已确认逻辑事件写到可执行尺度。至少要能从该事件及其文件级依赖中恢复：进入状态、事件功能、触发、人物动机、具体过程、当时知情、心理与关系位置、信息差、冲突与解决、已确认动作/细节/场景要求、离开状态和下游影响。字段可以合并表达，但语义不得缺项；已经确认的具体事件不能退化成一句抽象功能，也不能反过来补写原记录没有确认的对白和微动作。

## 5. 第一层：方向与结构

目标是建立本阶段的整体形状，同时给覆盖账本建立首轮映射。

Web Chat 应：

- 先复述已确定边界，避免重复提问；
- 按相邻主题分组提问，一组通常处理一个领域、三至六个问题；不要把多个互不相干领域压成一组八到十个选项；
- 用对比鲜明的方案帮助作者表达倾向，也允许作者直接改写方案；
- 记录想保留的体验、情绪、主题和叙事承诺，即“设计目标”；
- 明确本轮不设计的内容及其后置阶段；
- 每收到一轮回答，下一条先准确回显已采用决定、自定义补充和覆盖关系，再进入新问题。

为降低后续误判，Web Chat 每轮输出采用轻量三段式；不需要额外总结，也不需要作者重复确认：

1. **本轮作者确认**：完整回显作者的选择、组合、自定义改写、否定、例外以及对旧结论的覆盖；选择字母选项时必须展开被选方案的完整兼容语义，不能只写“212A”或缩成一句结论；不得把模型新增方案混入本段。
2. **模型解释与必要推导**：分开写可靠必要后果、高置信解释与可选建议。可靠推导需说明依据；可选建议必须明确仍未确认。
3. **下一轮问题**：问题、候选方案、推荐和答题方式集中放在此段。

旧记录没有这三个标题时，Agent 按相同语义边界分析，不能只靠标题或正则切割。

逐轮回显不是阶段总结。它用于防止长对话遗失作者原话，也兼容只保存 Chat 输出的记录方式。回显必须区分“作者确认”和“模型建议”。

进入第二层的条件：总体方向足以判断后续选择是否偏离，并且覆盖账本已经知道哪些领域仍为空。

## 6. 第二层：逐域补全、关键分叉与缺口

第二层必须逐域扫描本阶段覆盖表，而不是只挑 Chat 自认为有趣或“足以闭环”的问题。

需要询问：

- 不能由已有结论可靠推出的必要事实；
- 会改变因果链、人物动机、关系性质、结局或读者期待的选择；
- 缺失后项目 Agent 无法形成可用上游的规则；
- 两种实现都合理但代价不同的分叉；
- 上游确认无法覆盖的关键空白；
- 作者可能并未意识到、但会实际限制后续设计的现实条件。

可以不问：

- 已明确确认或已授权继承的内容；
- 能由现有确认唯一推出且推导链清楚的后果；
- 已说明归属下游阶段、不影响当前阶段闭环的微动作、过场和局部表现；
- 纯命名、格式和普通常识。

“不机械填表”只表示提问要合并、自然、有上下文，不表示可以漏掉整个领域。模型提出的具体方案必须标为建议，只有作者接受后才成为确认。

## 7. 第三层：冲突、后果与覆盖审计

第三层同时做压力测试和完整性复查：

- 新决定是否与有效上游或本轮早先决定冲突；
- 后文是否已经覆盖前文，覆盖关系是否明确；
- 人物是否有足够动机、信息和现实条件做出关键选择；
- 能力、时间、资金、空间、家庭、社会反应和证据链是否闭合；
- 一个选择会让哪些后续安排失效；
- 是否把设计目标和当前实现混为一谈；
- 每个覆盖领域是否已处于“已覆盖 / 已继承 / 可推导 / 明确后置 / 不适用”之一；
- 是否仍有会改变当前阶段方向、却被无意留空的问题。

若问题可以通过可靠推导解决，明确给出推导并在逐轮回显中标为 `DERIVED`。若仍有 `缺失` 的关键项，就继续定点提问；不能因为已经进入第三层而强行收口。

## 8. 三个独立事实维度

每条进入正式资料的结论都应分别判断以下三个维度。Web Chat 不需要在阶段末替项目 Agent 制作总表，但在对话中不能混淆它们。

### A. 决策状态

| 标签 | 含义 |
|---|---|
| `CONFIRMED` | 作者明确确认，可进入正式文件 |
| `TENTATIVE` | 作者表达倾向或允许暂用，后续可低成本替换 |
| `PENDING` | 暂未决定，不能伪装成事实 |
| `REJECTED` | 明确否定，用于防止旧方案回流 |

### B. 来源类型

| 标签 | 含义 |
|---|---|
| `DIRECT` | 作者在当前有效问答中直接表达确认、倾向、否定或明确授权 |
| `DERIVED` | 由其他当前有效事实可靠推出；必须写明依据和失效条件 |
| `INHERITED` | 来自作者指定参考资料，并经过本轮明确或批量授权；必须写明授权范围和参考来源 |

### C. 约束强度

- `HARD`：修改会改变核心承诺、底层规则、关键人物或主因果；
- `SOFT`：当前有效但允许在不破坏核心目标时调整。

例如，同一事实可以是 `CONFIRMED + DERIVED + HARD`，也可以是 `TENTATIVE + DIRECT + SOFT`。`L1—L4` 另行表示修改影响范围，不属于以上三个维度。

模型建议不是决策状态或来源类型。未被作者接受的建议不得进入正式事实。

## 9. 四层记录、编译模式与阶段交接

阶段结束时，Web Chat 不再输出“结构化设计总结”、决策总表或自称无遗漏的完成报告。它只需提示作者：将本阶段完整对话交给项目 Agent 编译。

作者按实际导出能力保存 Web Chat 的完整连续输出即可。若导出同时包含作者发言，一并保留；若只包含 Chat 输出，不视为记录不完整，但每轮“本轮作者确认”必须完整回显作者选择、自定义修改、否定和例外。保存格式和最短交接请求见 [`05-交付模板.md`](05-交付模板.md)。

项目 Agent 必须自己完成：按时序提取决定、后文覆盖前文、区分作者决定与模型建议、建立三个事实维度、独立覆盖审计、生成证据包与当前有效记录、编译正式资料和更新状态。Chat 在记录末尾附带的旧式总结仅可作为导航，不可作为编译依据。

### 9.1 四层资料的职责

- **原始记录**：作者保存的 Web Chat 连续输出，保留问题、选项、推荐、逐轮决定回显、否定、修改、重复和后文覆盖。它是最终历史证据，不改写、不压缩，不直接约束下游。
- **证据包 / 编译证据**：保存直接从原始记录生成的处理区逐字保全、来源行号或轮次、旧格式被选方案全文、覆盖关系、身份争议和迁移比对。它证明有效记录如何得到，但不是当前小说知识库。
- **当前有效记录**：保存本阶段当前仍有效的完整设计语义，包括事实、条件、例外、限制、心理、关系、知情、具体实现、因果、设计目标、读者体验约束、拒绝、后置和正式映射。允许主题化重排、合并和改写，但独立有效语义不得丢失；不再容纳逐字处理区、旧筛选稿或迁移期重复文本。
- **正式资料**：把全部当前有效、执行相关信息编译为下游可直接使用的权威接口。下游正常工作应优先只读正式资料；若经常必须下钻有效记录或证据包，说明正式资料编译不足。

四层都可保留，但职责不得混用。正常读取顺序固定为“正式资料 → 当前有效记录 → 证据包 → 原始记录”，满足任务所需后立即停止下钻。日常正文生产不得默认加载全部有效记录、证据包或原始记录。

### 9.2 两种编译模式

- **旧记录兼容模式**：适用于作者回答不在文件中、回显只有题号/字母或明显缩略、含旧式总结的历史记录。Agent 需要回查上一轮选项，把被选择方案与自定义修正的完整兼容语义恢复到证据包，再编译当前有效记录。
- **新版原生模式**：适用于按本文件三段式产生、每轮“本轮作者确认”已经完整展开选择、自定义修改、例外、否定和覆盖的记录。Agent 直接从确认区编译；默认不生成被选方案全文层，只有语义不足或发生证据争议时才回查上一轮选项并把结果写入证据包。

旧记录兼容机制不是未来记录的常规负担。无论使用哪种模式，证据只进入证据包，当前有效记录只承载当前语义。

### 9.3 Agent 的处理规则

1. **第一遍：原始记录到编译证据。** 从头到尾读取，以每条模型输出为单元划分“上一轮回答处理区”和“下一轮问题区”。证据包逐字保留处理区及题干定位，登记来源与覆盖证据；原始记录保持不变。
2. 只有清楚归因于作者的选择、改写、否定和授权可以标为 `DIRECT`。旧记录兼容模式中，回显若只确认字母选项、组合项或“按推荐项”，必须回到上一轮读取被选项全文，把与自定义修正兼容的条件、例外、背景、具体实现和叙事目的写入证据包。新版原生模式的确认区已经完整时，不重复恢复选项全文。
3. 下一轮**未选择**的选项、未获接受的推荐理由、示例答案和答题格式不进入有效事实。明确拒绝方案进入有效记录的拒绝/防回流部分。作者继续进入下一题不等于接受模型对上一轮的额外发挥。
4. 作者明确拒绝、作废或被后文覆盖的旧结论不再作为当前事实；有效记录保留“旧结论被何项覆盖”的语义，不需要复制整段失效正文。
5. 对信息去重和合并时，逐项检查是否新增条件、例外、因果、心理、关系、知情差、场景要求或叙事功能。只有没有任何语义增量的重复才能删除。
6. 有效记录按主题建立当前语义；简单事实用一个单元，复杂规则、人物或事件拆成必要部分，并保留覆盖、拒绝、后置、正式映射及必要来源定位。稳定编号只在有助于链接和覆盖追踪时使用，不复制证据包正文。
7. 证据包和有效记录文件头都列出适用来源、阶段、处理日期、覆盖顺序和处理者，并互相链接。复杂事件或关键规则应能从正式资料定位到有效记录对应章节，再由有效记录定位到证据包。
8. **第二遍：有效记录到正式资料。** 对每个当前有效信息单元标记正式落点、明确后置、仅建议、被覆盖或不适用；不得以“主题文件已大致提到”或“只是 `SOFT`”为由跳过条件和具体实现。
9. **第三遍：正式资料反向审计。** 检查遗漏的条件、例外和来源，建议误写为决定，旧规则回流，设计目标与当前实现混淆，以及人物心理、关系、信息差和事件过程被过度概括。
10. 不把 Agent 新创作的剧情混入有效记录。Agent 可靠推导单独标为 `DERIVED`；证据不足但可能影响核心方向时保留证据并提出最小问题。
11. 正式主题文件引用有效记录的具体主题章节，不直接链接原始记录；有效记录集中链接证据包，证据包再链接原始记录。
12. 审计每条当前有效信息是否属于**执行相关信息**：若删除它会改变后续设计、人物表现、知情、事件实现、现实条件或正文体验，就必须获得正式落点，无论其约束强度是 `HARD` 还是 `SOFT`。
13. 只有身份检查、语义覆盖、执行信息落点和一致性都通过，且不存在未处理的当前有效执行相关信息，阶段才能标为 `VALID`。
14. 对证据包中的信息逐项做“当前有效 / 被覆盖 / 仅解释或建议 / 证据不足 / 已编译落点”判断。不得把整段证据自动升级为当前事实，也不得留下只有证据包保存、却没有处理结论的独立有效信息。

若旧记录末尾包含 Chat 自行生成的阶段总结、结构化设计记录或“已问全”判断，不能把整段当权威，也不能因其是总结而整段屏蔽。Agent 必须逐项拆解：复述作者决定的回链到决定；可唯一推出的标为 `DERIVED`；只是建议的保留建议身份；与后文冲突的进入覆盖清单；其余证据不足项进入审计遗留。这样既防止总结冒充作者，也防止总结中出现的有效推导、背景形成史和实现限制被整体删除。

### 9.4 结构、命名与版本

原始记录、证据包和有效记录默认放在同一设计记录目录。证据包命名为 `YYYY-MM-DD-阶段或卷名-证据包.md`；有效记录命名为 `YYYY-MM-DD-小说基础模型-有效记录.md`、`YYYY-MM-DD-全书架构-有效记录.md` 或 `YYYY-MM-DD-第01卷设计-有效记录.md`。

同阶段有补问或 v2 修订时，可以保留各批次原始记录，但当前有效记录应合并全部适用批次并按最终覆盖关系维护。旧有效记录可标为 `DEPRECATED` 或删除；不能要求下游同时阅读多份互相覆盖的筛选稿。

有效记录按主题重排并建立章节级来源定位；证据包保存可直接核对的逐轮信息和必要的旧格式选项恢复；原始记录保存完整选项和时序。证据包无法解决“回答—解释—下一问—后文覆盖”争议时才回查原文。

### 9.5 职责边界

Web Chat 只负责充分访谈、按三段式准确回显与保留连续输出，不生成阶段总结、证据包或有效记录。作者只需保存原始记录。项目 Agent 负责模式判断、证据包、语义抽取、覆盖审计、有效记录、正式编译、链接与状态；不得把整理工作退回给作者或 Chat。

## 10. 停止条件

同时满足以下条件，Web Chat 才能结束该阶段问答：

- 阶段覆盖表中没有未经处理的 `缺失` 项；
- 所有关键项均已覆盖、获准继承、可靠推导、明确后置或说明不适用；
- 关键分叉已有决定，或作者明确将其后置且不阻塞当前阶段；
- 冲突和覆盖关系已经在逐轮回显中说清；
- 完整对话足以让未参与访谈的项目 Agent 独立恢复作者决定。

停止条件追求的是“覆盖完整且边界清楚”，不是把所有细节现在定死。不能以“下游以后还能补”为理由漏问当前阶段的核心内容，也不能为了填满模板提前锁死真正属于后续阶段的局部细节。
