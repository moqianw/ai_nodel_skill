# 小说项目模板｜完整项目初始化

此模板是**跨作品可复制的空项目**，不是示例小说，也不提供当前有效故事事实。结构配合根目录[通用工作流](../工作流/00-工作流总则.md)，供每本小说独立使用。

## 一、创建项目

推荐从仓库根目录执行：
```bash
python tools/new_novel_project.py --name 我的新小说 --slug 我的新小说
```
添加 `--activate` 会同时把根目录 `项目路由.md` 改为新项目。可用 `--check` 仅检查已有项目完整度；脚本禁止覆盖已存在的作品目录。也可手动将整个 `项目模板/` 复制到 `项目/<名称>/`，将 `{{PROJECT_NAME}}` 和 `{{PROJECT_SLUG}}` 统一替换，然后调整项目路由。

## 二、模板文件职责

- `项目说明.md`：作品身份、立项来源、引用工作流、当前使用边界。
- `AGENTS.md`：本书专属Agent限制，不能覆盖公共流程；默认仅定义未知与隔离边界。
- `项目状态.md`：阶段依赖、状态机和变更传播；默认阶段一UNBUILT，后续BLOCKED。
- `正式资料/01-小说基础模型/`：作品定位与世界、特殊机制、核心人物、关系、长期结局、审计。
- `正式资料/02-全书架构/`：全书因果、阶段/分卷、人物线、伏笔、结局和覆盖审计；默认BLOCKED。
- `正式资料/03-单卷设计/卷模板/`：每卷结构、逻辑事件、人物认知与现实连续性、审计；正式开始第X卷时复制为 `第XX卷/`。
- `正式资料/04-正文/`：授权样本文风功能抽样与迁移记录、文风/声线/PDM、章节状态与运行台账、完整章环境测试/验收；默认BLOCKED。
- `设计记录/`：原始、证据包与当前有效记录模板，仅本书使用。
- `测试运行/`：每次 run_id 的清单与验收记录，禁止与其他书共用。
- `出版物料/`：本书书名、简介、封面和出版发布记录；不复制其他书成果。
- `交付检查.md`：逐阶段进入条件、语义质量与归档检查。

## 三、状态与权限

初始 `01-小说基础模型=UNBUILT`，`02-全书架构=BLOCKED`，`03-单卷设计=BLOCKED`，`04-正文=BLOCKED`，测试未建立。模板的标题及空字段不是 `CONFIRMED`；填写文件不等于通过审计。只有作者决定具备可靠记录、正式资料完整编译和状态验收后，才可改为VALID。

阶段一VALID→允许阶段二；阶段二VALID→允许对应单卷；单卷VALID与正文声音/叙事决策模型适配且认可的完整章测试→可进入正式正文。上游修改按工作流传播DIRTY/STALE，不得仅改项目状态表让其合法化。

## 四、避免模板膨胀

字段是提示而非填空考核，简单事实可以合并；不能丢失会影响下游人物、关系、时间、世界或读者体验的执行信息。不适用的特殊机制/伏笔/知情规则写“不适用”，不得创造虚假设定凑齐格式。

本模板只覆盖新作品的文件骨架与执行边界；[公共交付提示词](../工作流/05-交付模板.md)与[工作流正文协议](../工作流/09-完整章节组装与连续生产.md)才规定分角色执行细节。
